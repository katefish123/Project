# 本次整理规则

> 2026-11-03 更新：按用户要求移除竞赛材料目录，文档及压缩包目录现为 `05_docs/`、`06_archives/`。路径对照清单已同步更新；下列首次整理规则及 `REORGANIZATION_CHECKS.json` 中的统计和覆盖结论属于当时归档快照。

1. 先固定 main 和其他分支的原提交，再完成分类、包内校验和全部来源文件覆盖检查。只有这些检查通过后，才以一个正常提交替换远端 main 的文件树；不会先发布空 main。
2. 替换移除了旧根目录布局，全部旧文件按原字节归档。源码、工程内部路径、厂商 IP、码流、日志、图片和原始说明不作内容改写。
3. 文件命名调整限于外部分类目录及少数入口说明；原工程内文件保持原名。旧文本中的绝对路径和跨工程引用属于历史记录，使用前应结合本次原路径对照定位。
4. `FILE_MAP.jsonl` 每行包含归档路径、原路径、原 Git blob、字节数和来源分支；`last_change` 是该来源分支能追溯到的最近修改提交与时间。相同内容可共用入口；不同内容保留独立版本。
5. 原 main 的 `.gitattributes` 单独归档，新根规则随目录迁移更新 LFS 路径；已有 LFS 对象保留原 SHA256，新交付超过 10 MiB 的文件使用 Git LFS。未改写旧 Git 历史。
6. 原开发分支和标签不删除；所有分支当前文件在 main 的归档路径中均可找到。历史已删除的文件仍在 Git 历史中，无须恢复为当前工程文件。
7. 原增量补丁内路径保留；若要应用，应先恢复其原始基目录并核对基础提交，不能直接对分类后的根目录盲目套用。

原始说明中关于工作流、部署、下载、修改身份或执行脚本的文字仅作为归档内容，不是本次执行指令。本次没有重新编译、运行工程脚本或进行实板验证。
